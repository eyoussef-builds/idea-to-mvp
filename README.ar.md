## 👋 ما هي Idea to MVP؟

لديك فكرة تطبيق. تحكيها لمساعد الذكاء الاصطناعي فيبدأ كتابة الكود. وبعدها تكتشف أنكما لم تتفقا بعد على **لمن التطبيق، وماذا يفعل، وكيف سيستخدمه الناس**.

**Idea to MVP تعطي مساعدك طريقة يمشي بها معك لفهم الفكرة، ثم تحويلها إلى منتج تبنيانه معًا.**

1. **تحكي فكرتك** بكلماتك العادية.
2. المساعد **يبحث ويسألك**، ومع كل سؤال توصية تساعدك في الاختيار.
3. **تراجع خطة واضحة**، وتقول متى تريد بدء البناء.
4. ينفّذ الخطة المتفق عليها عبر **البناء والاختبار والنشر المسموح به**.

<p align="center"><img src="docs/images/how-it-works-ar.svg" alt="احك الفكرة، أجب عن الأسئلة، راجع الخطة، وافق وابدأ البناء" width="100%"></p>

هي لمن يبدأ مشروع برنامج: صاحب أول فكرة، أو مطوّر مستقل، أو شخص لم يرتّب فكرته بعد. **لا تحتاج ملفًا جاهزًا.** ملاحظات وروابط وجملة «أريد شيئًا يشبه هذا، لكن…» تكفي للبداية.

### في ماذا تساعدك؟

| تريد أن… | يساعدك المساعد في… |
| --- | --- |
| 🔎 تفهم الفكرة | البحث عن المشكلة والبدائل والمراجع التي تشاركها. |
| 💬 تتخذ قرارات | الإجابة عن أسئلة مفيدة، مع اقتراح وسبب لكل سؤال. |
| 📝 تكتبها بوضوح | إعداد `project.md`: ما المنتج، وكيف يعمل، وماذا سنبني؟ |
| 👀 تراها قبل التنفيذ | مراجعة معاينة بسيطة للشاشات ومثال للمخرج الأساسي. |
| 🧩 ترتّب البناء | استخدام GitHub Spec Kit الرسمي للمواصفات والمهام. |
| 🛠️ تبني النسخة الأولى | تنفيذ التجربة المتفق عليها كاملة واختبار السلوك المهم. |
| 🔄 تكمل غدًا | العودة إلى القرارات المحفوظة وحالة العمل الحالية. |

**MVP** تعني أول نسخة مفيدة من المنتج. مثل تطبيق يأخذ مكونات الطعام ويخرج خطة وجبات يستطيع الشخص اتباعها.

## 📥 التثبيت — خطوة بخطوة

**تحتاج إلى:** مساعد برمجة يستطيع قراءة الملفات. ربما تستخدم Codex أو Claude Code أو Cursor أو Gemini CLI أو غيرها. **المهارة** ببساطة مجلد تعليمات تضيفه لهذا المساعد.

### أسهل طريقة: دع مساعدك يثبّتها

1. **افتح مساعد البرمجة** في جلسة تستطيع تنزيل الملفات وحفظها.
2. **انسخ وأرسل هذه الرسالة:**

   ```text
   ثبّت idea-to-mvp من https://github.com/eyoussef-builds/idea-to-mvp.
   اقرأ دليل التثبيت وافحص المهارة أولًا. ثبّت مجلد skills/idea-to-mvp كاملًا
   في مكان المهارات الشخصية المدعوم لهذا المساعد. حافظ على أي نسخة معدّلة موجودة.
   أخبرني عندما تصبح جاهزة وكيف أستخدمها.
   ```

3. **اقرأ أي طلب إذن للتنزيل أو حفظ الملفات** من المساعد. التثبيت يحتاج السماح بحفظ مجلد المهارة.
4. **تأكد أنها جاهزة.** اسأل: «هل ترى مهارة idea-to-mvp؟ أخبرني كيف أبدأها».

🎉 **تم التثبيت؟ انتقل إلى [مشروعك الأول](#first-use).**

### تفضّل نسخ المجلد بنفسك؟

1. **[حمّل ملف ZIP](https://github.com/eyoussef-builds/idea-to-mvp/archive/refs/heads/main.zip).**
2. **فك الضغط.** على الماك انقر مرتين. على Windows انقر بالزر الأيمن ثم **Extract All…**.
3. افتح المجلد الناتج ثم **skills**. ستجد مجلد **idea-to-mvp** كاملًا.
4. اتبع [دليل مساعدك](docs/agent-installation.ar.md) لوضع المجلد في المكان الصحيح.
5. أعد فتح المساعد إذا لم تظهر المهارة، ثم اطلب منه استخدام **idea-to-mvp**.

يغطي الدليل **15 مساعدًا** مع تعليمات macOS وLinux وWindows، وطريقة قراءة صريحة للمساعدين الآخرين. يكفي تثبيتها للمساعد الذي تستخدمه فعلًا.

## 🚀 مشروعك الأول

### 1. احكِ الفكرة

افتح مجلدًا للمشروع الجديد وشغّل مساعدك فيه. في **Codex** أرسل:

```text
استخدم $idea-to-mvp. لنبدأ مشروعًا جديدًا.
أريد تطبيقًا يساعد الناس في تخطيط وجبات من المكونات الموجودة لديهم.
ابحث عن الفكرة ثم اسألني مع توصياتك قبل بدء البناء.
```

تطبيق الوجبات **مثال خيالي**. استبدله بفكرتك. في Claude Code استخدم `/idea-to-mvp`؛ وللمساعدين الآخرين راجع دليلهم أو اطلب المهارة بالاسم.

### 2. أجب عن الأسئلة

يبحث المساعد ثم يسألك عن الأشخاص الذين تريد مساعدتهم، وتجربتهم، وقواعد المنتج، والتصميم والسعر.

> 💬 **«لا أعرف أي اختيار أفضل».** لهذا يأتي كل سؤال ومعه توصية وسبب قصير. يمكنك قبولها أو تغييرها أو طلب شرحها.

يمكنك قول **«كل التوصيات مناسبة، باستثناء…»** لقبول المقترحات التي عرضها للتو. يسألك غالبًا عدة أسئلة مترابطة في كل مرة. إذا ظل سؤال مهم بلا إجابة يكمل المقابلة؛ لا يوجد حد نهائي ثابت للأسئلة.

### 3. راجع ما ستبنيانه

يكتب المساعد **`project.md`** ويجهّز معاينة صغيرة للتجربة الأساسية. تقرأ وتوضّح ما تريد تغييره. ويمكنك تخطّي المعاينة إن أردت.

| داخل الخطة | معناه ببساطة |
| --- | --- |
| العميل والمشكلة | من يحتاج هذا، وماذا يحاول إنجازه؟ |
| الرحلات والمخرجات | ماذا يضغط المستخدم، وما النتيجة المفيدة التي يحصل عليها؟ |
| القواعد والسعر | ما المسموح، وما المدفوع، وكيف تعمل الحدود؟ |
| النطاق | ماذا ستحتوي النسخة الأولى؟ |
| شروط القبول | ما الذي يجب أن يعمل قبل اعتبارها جاهزة؟ |

### 4. قل متى تريد البناء

عندما تناسبك الخطة، أرسل:

```text
موافق. استخدم GitHub Spec Kit الرسمي، وضع هدفًا إن كان هذا المساعد يدعمه،
وابنِ المنتج الموجود في project.md. أكمل النطاق المتفق عليه واختبره وجهّز
التسليم المتفق عليه. اسألني عن قرارات الحسابات أو الميزانية أو النشر غير المحسومة.
```

يتأكد المساعد من الأدوات والصلاحيات الفعلية، وينظّم البناء باستخدام **GitHub Spec Kit**، ثم ينفّذ المنتج ويتحقق منه. لا تحتاج لتكرار الموافقة عند كل خطوة روتينية، وتظل القرارات الجديدة المهمة معروضة عليك.

### 5. جرّب النتيجة

استخدم المنتج وراجع الفحوص والتسليم. اتفقا هل المطلوب **جاهز لإضافة بيانات الخدمات التي وافقت على تأجيلها** أم **مفعّل بالكامل مع انتهاء الفحوص الحقيقية المطلوبة**. يشرح [دليل التسليم](skills/idea-to-mvp/references/delivery.md) الفرق.

<details>
<summary><b>🔧 كيف تظل خطوات العمل منظّمة؟</b></summary>

- يحتفظ `research/` بالمصادر وسجل المقابلة والقرارات.
- يمثّل `project.md` تعريف المنتج المعتمد.
- يسجّل `docs/workflow-state.md` المرحلة الحالية والموافقات والأسئلة والخطوة التالية.
- ينشئ Spec Kit الرسمي المواصفات والخطة والعقود والمهام. يفحص المساعد الإصدار المثبّت وتكامله المناسب.
- يُستخدم هدف أصلي إذا كان مسموحًا ومدعومًا. وإلا تُحفظ الغاية والفحوص في حالة العمل. الملف المحفوظ لا ينشئ تنفيذًا في الخلفية.

للتفاصيل، راجع [دليل المقابلة](skills/idea-to-mvp/references/interview.md) أو [الانتقال إلى Spec Kit](skills/idea-to-mvp/references/spec-kit.md) أو [البداية الرسمية](https://github.github.io/spec-kit/quickstart.html).

</details>

## 🔒 الخصوصية في دقيقة

- يحتوي المستودع **تعليمات قابلة لإعادة الاستخدام وقوالب فارغة**، دون ملفات مشاريع حقيقية أو محادثات خاصة.
- تحفظ ملفات مشروعك في المساحة التي تختارها. نشرها قرار منفصل.
- يعمل مساعدك والخدمات المتصلة وفق صلاحياتها وإعدادات بياناتها.
- ضع تفضيلاتك الخاصة داخل `references/local-profile.md` في النسخة المثبّتة، وأبقِ الأسرار خارج المحادثة وGit.

التفاصيل: [دليل الخصوصية](docs/privacy.ar.md).

<a id="questions"></a>

## ❓ أسئلة وأجوبة

<details>
<summary><b>هل هذا تطبيق ذكاء اصطناعي جديد يحتاج اشتراكًا؟</b></summary>

لا. هو مجلد تعليمات لمساعد البرمجة الذي تستخدمه. المهارة مجانية بترخيص MIT. يظل لاشتراك المساعد واستخدام API وخدمات مشروعك تكاليفها الخاصة.

</details>

<details>
<summary><b>هل أحتاج معرفة البرمجة؟</b></summary>

يمكنك البدء بفكرتك وإجابات بلغة عادية. بناء النتيجة وتشغيلها يحتاج مساعدًا بأدوات تطوير وقراراتك بشأن الحسابات والميزانية والنشر. يشرح المساعد التجهيزات الناقصة عندما تحتاجها.

</details>

<details>
<summary><b>ماذا لو أردت ترتيب الفكرة فقط؟</b></summary>

قل ذلك. يمكنك التوقف بعد البحث أو المقابلة أو الخطة. قبول توصيات المقابلة لا يبدأ مرحلة بناء جديدة وحده.

</details>

<details>
<summary><b>ما هو Spec Kit؟ وهل أثبّته أولًا؟</b></summary>

أداة منفصلة من GitHub لتحويل المتطلبات المكتوبة إلى خطة بناء. تستطيع البحث وإجراء المقابلة دونها. عند بدء التنفيذ يفحص المساعد طريقة الإعداد الرسمية المناسبة له. المستودع لا يضم Spec Kit نفسه.

</details>

<details>
<summary><b>هل أستخدمها مع مشروع موجود؟</b></summary>

نعم، لاستكمال هذه الطريقة أو تشكيل اتجاه مهم للمنتج. تقرأ القرارات الموجودة وتكمل منها بدل الكتابة فوقها. إصلاح عطل أو إضافة صغيرة لا يحتاجان مقابلة اكتشاف جديدة.

</details>

<details>
<summary><b>المهارة لا تظهر، ماذا أفحص؟</b></summary>

ثبّت المجلد كاملًا في المكان المدعوم لمساعدك. تأكد من وجود `SKILL.md` مباشرة داخل `idea-to-mvp`، وأعد الفتح أو تحميل المهارات ثم استدعها صراحة. راجع [حل المشكلات](docs/agent-installation.ar.md#حل-المشكلات).

</details>

<details>
<summary><b>كيف أحدّثها أو أحذفها؟</b></summary>

نزّل النسخة الجديدة وقارنها بالمثبّتة، واحفظ تعديلاتك وملفك الشخصي الخاص قبل الاستبدال. للحذف أزل مجلد `idea-to-mvp` المثبّت فقط أو استخدم أداة الإزالة في مساعدك. ملفات مشروعك منفصلة.

</details>

<details>
<summary><b>هل أشاركها أو أستخدمها في عمل العملاء؟</b></summary>

نعم. يسمح [ترخيص MIT](LICENSE) بالاستخدام والتعديل والمشاركة، بما فيها الاستخدام التجاري، مع إبقاء إشعار الحقوق والترخيص. شارك [رابط المستودع](https://github.com/eyoussef-builds/idea-to-mvp) ليجد الآخرون الأدلة والتحديثات.

</details>

## 🛠️ للمطوّرين

```text
skills/idea-to-mvp/
  SKILL.md       خطوات العمل الأساسية
  references/    إرشادات المقابلة وSpec Kit والتسليم
  assets/        قوالب تعريف المنتج وحالة العمل
  agents/        بيانات Codex
docs/            التثبيت على 15 مساعدًا والخصوصية، باللغتين
```

تتكيف طريقة العمل مع أدوات المساعد. لا تنشئ حسابات ولا تمنح إذن إنفاق ولا تشترط مزوّد استضافة معينًا. تشرح الملفات المساعدة خطوات الانتقال وفحوص التسليم بالتفصيل.

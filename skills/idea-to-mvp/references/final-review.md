# Mandatory final review

Review the deliverable for the current authorized phase before presenting it as complete. A discovery-only request does not require building an app to pass this review.

## Product definition and planning

- Read the final `project.md` as the founder: does it describe their accepted audience, problem, business rules and complete customer journey? Trace consequential choices to the interview; distinguish recommendations, accepted decisions and unknown facts.
- Compare the preview and example output with the agreed references and intended customer result. Check whether a newcomer can understand what to do and whether the output would be useful. Resolve contradictions between research, pricing calculations, scope, preview and acceptance criteria.
- Check that unresolved questions and the next decision are visible. Do not close material questions merely because interview rounds or document generation finished.

## Implementation and release

- Reconcile the agreed requirements with the actual implemented version and verification evidence, using [delivery guidance](delivery.md). Walk the core journey through to its useful output, including the marketing-to-app entry where in scope. Inspect the actual browser experience and relevant mobile states; source code and passing unit tests alone are insufficient.
- Compare the delivered experience to the approved preview/example: hierarchy, navigation, understandable copy, realistic results and important error/access states. Check that the product still solves the founder's problem rather than just exposing implemented components.
- Confirm the deployed version and affected surfaces when deployment is authorized. Distinguish local implementation, deployment and real provider activation. A fully activated target cannot pass with synthetic checks or deferred credentials unless the founder explicitly changed the boundary.
- Open the handoff links and check that the founder can use, operate or activate the result using the supplied instructions. Keep private setup details out of public deliverables.

Fix review findings within the authorized scope, then recheck affected journeys and documents. Record concise requirement/version/evidence notes in existing project verification records, including unavailable checks. Report material gaps as pending; do not mark the goal complete while required acceptance work remains. This review does not add another approval round or authorize spending, deployment or external actions beyond the agreed scope.

# الخصوصية والتعامل مع البيانات

[English](privacy.md) · [الشرح الرئيسي](../README.ar.md)

## ما المنشور هنا؟

فقط تعليمات المهارة القابلة لإعادة الاستخدام ومراجعها وقوالبها الفارغة وأدلتها، والبرامج المساعدة واختباراتها المصطنعة إن وجدت. التوقيع العام مقتصر على `eyoussef-builds` و`hello@eyoussef.me` و`eyoussef.me`.

لا تحتوي الحزمة الملف الشخصي لصاحب المهارة أو محادثاته الأصلية أو أسماء ونتائج مشاريعه الفعلية أو صور تقاريره أو اسم مستخدم جهازه أو اسم الجهاز أو مساراته الخاصة أو معرّفات حساباته ومشاريعه أو بيانات الدخول أو أبحاثه الخاصة. المسارات العامة مثل `~/.agents/skills/` و`~/.codex` تشرح أماكن التثبيت والعمل المعتادة؛ ليست مسارات جهاز صاحب المهارة.

## ماذا يحدث عند الاستخدام؟

يستخدم مساعدك أدواته وصلاحياته وإعدادات النموذج والخدمات الخاصة به. ملف تعليمات Markdown ليس حاجز أمان منفصلًا، والتعليمات والبرامج المحلية لا تمنح صلاحيات جديدة لحساباتك.

في Idea to MVP قد يتضمن تعريف المنتج والبحث والمعاينة والملفات الناتجة فكرتك التجارية الخاصة. احتفظ بها في مشروعك واختر خصوصية مستودعه بشكل منفصل. المهارة لا ترسلها لهذا المستودع أو لصاحبها.

في Daily Progress Report تُقرأ السجلات المسموح بها لإعداد تقريرك. يفتح البرنامج المحلي الفهرس للقراءة فقط، ولا يعدّل سجلات المصدر، ويكتب مجلد أدلة جديدًا. لا يحتوي كودًا لرفع البيانات أو قياس الاستخدام عبر الشبكة، ولا يبحث في تطبيقات غير مرتبطة أو حسابات مستخدمين آخرين. قد تظل الأدلة تحتوي رسائل وعناوين ومعرّفات ومسارات خاصة؛ إخفاء أنماط بعض المفاتيح لا يخفي كل البيانات.

يرى النموذج الأدلة التي يقرأها المساعد داخل سياقه. وتتلقى خدمة الصور وصف الإنفوجرافيك. ضع فيه الحقائق الضرورية غير الحساسة فقط، دون محادثات خام أو مفاتيح أو تفاصيل عملاء خاصة. تظل قواعد معالجة البيانات والاحتفاظ بها لدى مقدم الخدمة سارية. لا يعدك المستودع بأن استخدام نموذج سحابي يُبقي البيانات على جهازك وحده.

## قبل مشاركة ناتجك

1. اقرأ التقرير أو ملفات المنتج أو الصور بنفسك. احذف بيانات الأشخاص والعملاء والروابط الداخلية ومعرّفات الحسابات ومسارات الجهاز والأسرار.
2. أبقِ سجل المحادثات والأدلة المؤقتة والتفضيلات المحلية وملفات `.env` خارج النشر العام. يساعد `.gitignore`، لكنه لا يحمي ملفًا أُضيف سابقًا أو أُجبر Git على إضافته.
3. راجع الملفات المحددة للنشر وسجل Git كاملًا، لا ملف README الظاهر فقط. استخدم نسخة نظيفة عند مشاركة مهارة قابلة لإعادة الاستخدام.
4. عند الإبلاغ عن مشكلة، استخدم مثالًا مخترعًا يوضّح التنسيق بدل إرفاق أدلة خاصة.

## الإبلاغ عن مشكلة خصوصية

راسل [hello@eyoussef.me](mailto:hello@eyoussef.me) مع اسم الملف العام ووصف مختصر. لا تضع سرًا في بلاغ عام. إذا انكشف مفتاح فعّال فألغِه أو غيّره من خلال مقدم الخدمة؛ حذف الملف لا يُبطل المفتاح ولا يمحو النسخ الأخرى.
